# Архитектура

Карта кода для того, кто открыл проект впервые. Всё — ванильный ES5+, модули
оформлены как IIFE и вешают себя на единый глобальный объект `window.ICH`.
Сборки нет: `index.html` подключает файлы тегами `<script>` по порядку.

## Модули

| Файл | Экспорт | Отвечает за |
| --- | --- | --- |
| `src/core.js` | `ICH.U`, `ICH.P`, `ICH.C` | математика, сид-рандом, смешивание цветов, палитра, константы и размеры кадра |
| `src/scores.js` | `ICH.Scores` | две таблицы рекордов в `localStorage` (сегодня и всё время), ник, разметка |
| `src/share.js` | `ICH.Share` | карточка забега на офскрин-канвасе и отдача её в системное окно «поделиться» |
| `src/zones.js` | `ICH.Zones`, `ICH.FinalZone`, `ICH.Theme` | пять районов и площадь огня; `Theme` плавно перетекает между их палитрами |
| `src/audio.js` | `ICH.Audio` | синтез всех звуков и секвенсор музыки |
| `src/input.js` | `ICH.Input` | клавиатура, экранные кнопки, геймпад |
| `src/fx.js` | `ICH.FX` | пул частиц, всплывающий текст, тряска, вспышки, слоумо |
| `src/art.js` | `ICH.Art` | отрисовка героя, врагов, платформ, реквизита, снарядов |
| `src/world.js` | `ICH.Backdrop`, `ICH.Level` | параллакс-фон и генератор бесконечной улицы |
| `src/entities.js` | `ICH.Ent` | физика героя, ИИ врагов, снаряды, бонусы |
| `src/boss.js` | `ICH.Boss` | шесть боссов: поведение, отрисовка, урон, трофеи |
| `src/hud.js` | `ICH.HUD` | интерфейс поверх канваса |
| `src/game.js` | `ICH.Game` | состояние, правила, столкновения, камера, главный цикл |

Зависимости строго вниз по этому списку: `art` не знает про `world`, `world` не
знает про `game`. Исключение — обратные ссылки времени выполнения через
`ICH.Level` / `ICH.Game` там, где сущностям нужно что-то заспавнить.

## Системы координат

Их три, и путать их дорого.

**Мировые.** В них живут платформы, враги, бонусы. `x` растёт вправо без предела,
`y` растёт вниз. Мостовая — `C.GROUND_Y = 430`. Ниже `C.DEATH_Y = 720` — падение.

**Экранные (логические).** Кадр `C.W × C.H`, по умолчанию 960×540. Мир
переводится в экран сдвигом на камеру: `ctx.translate(-camX, -camY)`. В экранных
координатах работают фон, HUD и баннеры.

**Устройства.** Реальные пиксели канваса. Перевод — единственной матрицей в
начале `Game.draw()`: `setTransform(cv.width / C.W, 0, 0, cv.height / C.H, 0, 0)`.

Кадр **адаптивный**: `C.W`/`C.H` растут по той оси, где у экрана есть запас, и
упираются в ограничители (ширина 960…1400, высота 540…820). Поэтому:

- горизонт фона считается от низа: `C.H - 240`;
- камера держит мостовую на постоянном расстоянии от низа: `C.H - 140`;
- HUD рисуется с увеличением `C.HUD` и раскладывается по `C.W / C.HUD`.

## Порядок отрисовки

```
небо → облака → море → 4 слоя параллакса → тень «колодца»
  ├ смещение на камеру ─────────────────────────────────
  │   настенный декор → тьма под мостовой → платформы
  │   → наземный декор → препятствия → кувшины → канаты
  │   → бонусы → враги → босс → снаряды → герой → частицы
  └──────────────────────────────────────────────────────
передний силуэт → виньетка → HUD → баннер района → вспышка
```

## Генерация уровня

`Level` держит плоские массивы (`platforms`, `enemies`, `pickups`, `hazards`,
`decos`, `ropes`, `jars`, `bosses`) и наращивает их вперёд по мере движения
камеры, вырезая всё, что осталось далеко позади.

Улица собирается кусками. `Level.addChunk()` выбирает шаблон из таблицы текущего
района (`street`, `gap`, `stairs`, `rooftops`, `ropes`, `bazaar`, `wall`,
`arcade`), а каждые 4-7 кусков вклинивает **арену босса**: закрытый двор, ворота
в котором добавляются в `platforms` при входе и убираются со смертью босса.

Порядок районов жёсткий: `qala → bazar → damlar → hamam → deniz → площадь огня`,
после финала `Level.lap++` и круг начинается заново со сложностью выше.
Метки районов (`Level.marks`) позволяют `zoneAt(x)` сказать, какой район сейчас
на экране — по ним же `Game` переключает палитру, музыку и баннер.

Вся генерация детерминирована: `U.rng(U.hash(seed, index))`. Один и тот же кусок
всегда собирается одинаково, поэтому фон можно выгружать и восстанавливать.

## Часы симуляции

`Game.loop` не отдаёт в `update` кадровую дельту. Она копится в `Game.acc`, а мир
считается фиксированными шагами `C.STEP` (1/60 с), не больше `C.MAX_STEPS` за
кадр. Причина в том, что гравитация интегрируется: на кадровой дельте прыжок
выходил 106 px на 30 Hz и 116 px на 144 Hz — разная игра на разных мониторах и
несопоставимая таблица рекордов. Горизонталь не плыла: там скорость
присваивается, а не интегрируется.

Три следствия:

- **`update` вызывается только с `C.STEP`.** Тесты гоняют `g.frames(hz, сек)`
  через настоящий `loop`, а не `update(1/60)` напрямую, иначе кадровые баги
  невидимы.
- **Кадр без шага не рисуется.** На 120 Hz это вдвое меньше работы, а на паузе
  мир заморожен и хватает одной отрисовки. Принудительный перерисовыв —
  `Game.dirty`, его ставят `resize()`, `show()` и `hideScreens()`.
- **Провал времени отбрасывается.** Вкладка, проспавшая полминуты, не
  проматывает мир: накопитель обнуляется на потолке шагов.

## Город дня

Улица и фон целиком выводятся из `U.hash(...)` — никакого `Math.random` в
`world.js` нет. В хэш подмешан `U.seed`, который `Game.newRun()` ставит из
`U.daySeed(U.today())`. Отсюда: город один и тот же у всех, кто играет сегодня,
и другой завтра. Внутри забега сид постоянен, поэтому фоновые ячейки
восстанавливаются один в один, когда возвращаешься назад.

Случайность боёв (`boss.js`, часть `game.js`) осталась на `Math.random` — она
намеренно не в этом потоке: иначе число бросков в бою сдвигало бы генерацию
следующего куска улицы, и город перестал бы быть воспроизводимым.

## Тонкие места

**Просвет над улицей.** `Level.block()` поднимает любую сплошную плиту, которая
оставила бы над мостовой меньше 64 px: герой ростом 56 px под такой застревает
намертво — под ней не пройти, а запрыгнуть мешает она же.

**Защёлка ввода.** События приходят асинхронно, игра читает ввод раз в кадр.
`Input.press()` ставит флаг в `latch`, который живёт до конца кадра, поэтому тап
короче кадра не теряется.

**Слой управления выше меню.** Экранные кнопки обязаны быть поверх канваса,
поэтому `#touch` лежит над `.screen`. Показывать его можно только в игре
(`body.in-game`): иначе зона стика — левые 46% экрана — съедает тапы по левой
половине любого меню.

**Спрыгивание с навеса.** `p.dropT` — таймер, а не флаг: условие, пересчитанное
из `grounded`, гаснет в тот же кадр, и герой ловит ту же доску обратно.

**Кэш и размер кадра.** Всё, что зависит от `C.W`/`C.H`, строится каждый кадр.
Единственный кэш — виньетка, и она сбрасывается в `Game.resize()`.

## Настроенные константы

Всё в `C` (`src/core.js`). Менять по одной и прогонять тесты — они проверяют,
что прыжок берёт шаг лестницы, а подкат приседает.

| Константа | Значение | Почему так |
| --- | --- | --- |
| `STEP` / `MAX_STEPS` | 1/60 с / 5 | шаг симуляции и потолок догона за кадр |
| `GRAVITY` / `JUMP_VEL` | 2100 / −705 | одиночный прыжок берёт подъём до ≈ 102 px — выше любого шага генератора (максимум 84 px) |
| `DJUMP_VEL` | −615 | двойной добирает до ≈ 162 px |
| `RUN_SPEED` | 335 | дальность прыжка ≈ 250 px, шире самой широкой пропасти |
| `COYOTE` / `JUMP_BUFFER` | 0.1 / 0.13 с | прощает кадр опоздания на краю и до приземления |
| `SLASH_BUFFER` | 0.18 с | короче отката сабли (0.3 с) намеренно: буфер ловит тап на исходе, а не воскрешает старый |
| `NUDGE` | 9 px | на столько подвинет вбок, если задел угол плиты головой |
| `STICK_DEAD` / `STICK_MAX` | 10 / 16 px | сумма — ход разворота стика, около 4 мм по стеклу |
| `CAM_LEAD` / `BACKTRACK` | 340 / 560 | камера впереди героя; назад можно уйти, пока улица не выгружена |
| `INVUL_TIME` | 1.25 с | хватает выйти из толпы после удара |
